# 04 · 素材与截图

片子的说服力几乎全在截图里。这一页讲**怎么拿到能用的截图**。

## 素材优先级

1. **产品自己的真机截图** —— 最好。项目仓库里的 `demo_video/`、`docs/`、`screenshots/` 先翻一遍。
2. **官网/小程序/App 的公开页面** —— 用浏览器按 2x 截，得到 3840×2160。
3. **用户提供的素材** —— 只要一次，问清楚哪几张是「最能说明问题」的。
4. 代码重绘的假界面 —— **只用于两种情况**：真实截图涉及隐私需要替换，或模板自带的 demo。

## 截 4K 图

```bash
python3 scripts/shot.py <网址> <名字>              # 1920×1080 @2x → 3840×2160
python3 scripts/shot.py --login <网址>             # 先弹窗登录，再截
python3 scripts/shot.py --mobile <网址> <名字>     # 390×844 @3x，竖屏小程序
python3 scripts/shot.py --clip 0,0,1920,3000 <网址> <名字>   # 只截长图的一段
```

- 需要登录的页面：`--login` 会打开真实窗口，**请用户自己登录后关掉窗口**，脚本接着截。
- 截完统一进 `public/img/`，文件名用英文小写下划线，比如 `chat_card.png`。

## 挑图：先做联系表，别一张张点

```bash
python3 scripts/sheet.py public/img/phone out/contact.jpg   # 拼成一张总览图
python3 scripts/images.py crop public/img/phone/chat_card.png 0.5 0.2 0.4 0.3   # 预览裁切
```

- 一张张看会漏掉「文章后半段才出现的好图」。先拼图，一起看。
- **585×1346 这类竖屏截图最多只能放大到 width 430**（1080 高下），所以关键信息必须在
  截图的上 2/3，否则推近之后要露出来。

## 每段配图的硬指标

| 指标 | 要求 |
|---|---|
| 每个功能段落 | ≥1 张真实截图或真实作品图 |
| 全片 | ≥8 张不同的真实截图 |
| 快切蒙太奇 | 至少一段由 8 张以上截图组成，每张 0.5 拍 |
| 比例 | 一律保持原图宽高比，用 `Phone` 的 `ratio` |
| 焦点 | 信息太小就 `zoom 1.4–2.2` + `fx/fy`，不要硬拉大整张图 |

## 事实核实（会被抓的地方）

- 屏幕上写的每句说明都要能在出处里找到。**别给案例加原帖没说的定语**（"纯 SVG"、"七种画风"
  "最近才火"这类，都是容易写错的）。
- 二手报道只当线索，必须追到原帖/官方页面。
- 数据要标出处：`README` 的实测表、官方公告、后台截图。**宁可少说一个数字，不要编一个。**
- 展示的作品必须真是这个产品做出来的。别家的演示图再好看也不能冒充。

## 音乐

```bash
python3 scripts/music.py analyze audio-src/music.mp3     # bpm / beat / bar / 一致性 / 小节能量
python3 scripts/music.py grid   audio-src/music.mp3      # 打印每个拍点的时间
python3 scripts/music.py bars   audio-src/music.mp3      # 逐小节能量，找爆发点
```

选曲标准（按重要性排）：

1. **第 4–5 秒就能进入爆发**，或者前奏可以剪掉。开场情绪段允许没有鼓。
2. **全片至少 2 次爆发**，第二次落在 55–58 秒最好（片尾落定）。
3. **节拍一致性 ≥ 0.9**，否则快切卡不准。
4. 没有人声（有旁白时尤其）、没有突兀的音效采样。

没有合适音乐时：**用静音占位，先把画面做完**，别用一段不搭的曲子凑。
`public/audio/mix.wav` 默认就是 16 秒静音占位。
